# snatch-dash

[English version](README.md)

**snatch-dash** — открытое приложение для приборки мотоцикла:
навигация, история поездок, учёт обслуживания мотоцикла, расходы и
карточки медиа/звонков в одном лёгком приложении.

Приложение рендерит собственное изображение для дэша за кадром, кодирует его
в H.264 и стримит по Wi-Fi, так что экран телефона может оставаться
выключенным во время поездки.

Это **Flutter-порт [subtlesayak/open-dash](https://github.com/subtlesayak/open-dash)**
(оригинальное нативное приложение на Kotlin/Compose), переработанный на
**картографических и навигационных сервисах Yandex** (Yandex MapKit) вместо
Google Maps — чтобы надёжно работать **на территории Российской Федерации**,
где картографические/геолокационные сервисы Google недоступны или работают
нестабильно.

**Android 10+ (API 29)**. Язык интерфейса — русский или английский, по языку
устройства; переключателя языка в приложении нет.

## ✨ Возможности

- 🧭 Навигация на байк-дэше по автомобильным маршрутам Yandex MapKit,
  предпросмотр карты в приложении, ETA, оставшееся расстояние, статус GPS и
  пересчёт при отклонении от маршрута.
- 🗺️ Офлайн-карты для дэша — паки `.pmtiles` по субъектам, качаются системным
  `DownloadManager`, проверяются по sha256 и рисуются на устройстве через
  MapLibre. **Дэшу нужен хотя бы один пак**: без него навигация в приложении
  заблокирована (маршрутизация и поиск по-прежнему требуют сети — см.
  «Известные пробелы»).
- 🏍️ Профили техники с выбором активной техники, пробегом, датами
  ТО/страховки и данными об обслуживании.
- 🧰 Гараж с интервалами по расходникам, историей обслуживания,
  редактированием пробега и расчётом пробега по заправкам.
- ⛽ Расходы по категориям: топливо, ремонт, аксессуары, экипировка, еда,
  проживание, транспорт и прочее, с фильтрацией по месяцу/за всё время и
  экспортом в CSV/HTML через системное меню «Поделиться» Android.
- 🎵 Карточки медиа/звонков, обложки, индикаторы PLAYING/PAUSED и управление
  воспроизведением, треками и громкостью музыки кнопками дэша. Для интеграции
  медиа нужен доступ к уведомлениям Android; поддержка зависит от плеера и
  прошивки приборки.
- 🗣️ Голосовые манёвры на 300/150/60 м, прибытие и оповещения о связи с дэшем.
  В «Ещё → Голосовые подсказки» — включение, громкость речи 25/50/75% и
  поведение музыки: приглушать, ставить на паузу с восстановлением или не
  менять. Настройки сохраняются между запусками; речь использует Android TTS
  и аудиофокус.
- 🔔 Локальные напоминания о наступающем ТО.
- 🔒 Хранение данных только локально (SQLite через `sqflite`); без облачной
  синхронизации, без аккаунта.

## 📦 Архитектура

Две половины, разделённые по границе Android API:

- **Flutter/Dart-приложение** (`lib/`) — весь UI, состояние (Riverpod),
  локальное хранилище (`sqflite`), карта внутри приложения
  (`yandex_maps_mapkit`), навигационная математика и жизненный цикл
  (`lib/nav/`: прогресс по маршруту, отклонение, ETA и голосовые подсказки).
- **Нативный Android-плагин** (`packages/opendash_dash_engine`) — всё, что
  обязано оставаться нативным: Wi-Fi-сопряжение с дэшем + сессия протокола
  K1G, конвейер закадрового рендера «карта → оверлеи на `Canvas` →
  `MediaCodec` H.264 → RTP», GPS-трекинг, настроенный под поездку, интеграция
  MediaSession/notification-listener и telecom, Android TTS/аудиофокус.
  Dart передаёт обновления навигации, не перенося кадровый цикл на UI-поток
  Flutter.

Граница плагина задана в
[`pigeons/dash_engine.dart`](packages/opendash_dash_engine/pigeons/dash_engine.dart):
Pigeon генерирует типизированные Dart/Kotlin-команды и потоки состояния,
кнопок и отладочного лога. Менять нужно схему и перегенерировать обе стороны,
а не править generated-файлы или вручную поддерживать строковый контракт каналов.

Закадровый рендерер, который стримится на физический дэш, **не** использует
тайлы карты Yandex — у Yandex MapKit нет публичного, переиздаваемого API
сырых тайлов для композитинга вне собственного `MapView` (то же ограничение,
что и у Google Maps). Он рисует через **MapLibre Native в offscreen-режиме
поверх локальных паков `.pmtiles`**, собранных из данных OpenStreetMap
конвейером [`tools/planetiler`](tools/planetiler) и раздаваемых с S3; маршрут,
стрелка райдера, пин назначения и пилюли статуса накладываются поверх через
`Canvas`. Конвейер кадра, сборка стиля и модель нескольких источников описаны в
[`spec/drawing_from_local_tiles.md`](spec/drawing_from_local_tiles.md), формат
корпуса и протокол скачивания — в
[`spec/remote_map_server.md`](spec/remote_map_server.md).

Данные карты — © OpenStreetMap contributors (ODbL); стили и спрайты из
OpenMapTiles (CC BY 4.0), глифы — Noto Sans (SIL OFL 1.1), сам MapLibre Native
под BSD-2-Clause. На кадре дэша атрибуции намеренно нет — на 526×300 под
круглым безелем она съедает заметную долю кадра, — поэтому она живёт в
«Ещё → О приложении». Разбор по файлам:
[`ATTRIBUTION.md`](packages/opendash_dash_engine/android/src/main/assets/ATTRIBUTION.md).

## 🚧 Известные пробелы относительно оригинального приложения

- Нет облачной синхронизации / входа в аккаунт — опциональная синхронизация
  через Firebase в оригинале здесь убрана полностью; всё хранится только
  локально.
- Глифы манёвров уходят на дэш по шагам (повороты, развилки, развороты,
  круговые с направлением вращения и номером съезда, паромы — см.
  `_dashCodeByType` и `Maneuver.dashCode` в `lib/nav/route.dart`), но **на
  живом дэше проверен только `0x09`** («прямо»), он же запасной вариант для
  всего неразмеченного. Остальные взяты из таблицы глифов прошивки и ждут
  подтверждения заездом.
- Офлайн сделан наполовину: **карта** на дэше рисуется без сети, а
  **маршрутизация и поиск места назначения по-прежнему ходят в Yandex по
  сети**. Поездка по уже построенному маршруту переживёт потерю связи;
  построение нового маршрута и пересчёт после отклонения — нет. Варианты, чем
  это закрывать, разобраны в
  [`docs/offline_mode_ru.md`](docs/offline_mode_ru.md).
- Паки покрывают зумы 10–15 (корпус пересобран 09.09.2026, лестница в
  приложении — 10.00–15.00). Обзор поездки целиком офлайн всё равно
  недоступен: на самой широкой ступени в кадр 526×300 влезает около 20 км,
  так что маршрут на 300 км на один экран не помещается.
- Адаптивное переключение fps/битрейта есть, но опирается на другой признак,
  чем в оригинале. Порт снижает 4 fps/200 кбит/с → 2 fps/100 кбит/с, когда
  карта перестаёт двигаться (скорость с гистерезисом, `FrameRatePolicy`), а
  оригинал смотрел на расстояние до следующего манёвра — поэтому длинная
  прямая на скорости здесь по-прежнему идёт на высокой частоте. См.
  [`spec/video.md`](spec/video.md).
- Погода ещё не реализована: на приборку уходят константы «солнечно» и
  +25 °C, а не фактические погодные данные.
- Базовое управление медиа, обложки, PLAYING/PAUSED и inactive подтверждены
  райдером на Huawei HBN-LX9 и Xiaomi 2606FRN72Y 26.10.2026. Границы передачи
  обложек, взаимодействие с видеопотоком, независимые громкости и расширенная
  матрица кнопок остаются открытыми проверками на железе — см.
  [план мультимедиа](plans/active/2026-10-04-multimedia-support.md).
- RuVoice, голосовые манёвры, пороги срабатывания, работа с музыкой и
  оповещения при выключенном экране подтверждены райдером на Huawei HBN-LX9
  (Android 12) 27.10.2026. Это не проверка всех музыкальных политик,
  громкостей, прибытия, английского TTS или аудиофокуса на Android 15+ — см.
  [план голосовых настроек](plans/active/2026-10-25-voice-settings.md).

## Установка и обновления

Скачайте APK из [GitHub Releases](https://github.com/RPG-18/snatch-dash/releases)
и при запросе Android разрешите установку из выбранного источника.
«Ещё → Обновления» поддерживает stable (по умолчанию) и nightly.
Тумблер автоматического обновления управляет проверкой на старте; ручная
проверка, скачивание и системная установка доступны и при выключенном тумблере.

## 🛠️ Сборка из исходников

Нужны Flutter (проверено на **Flutter 3.44.6 / Dart 3.12.2**),
Android SDK с API 36 и настроенным `ANDROID_HOME`/`sdk.dir`, а также
**JDK 21** для запуска Gradle.

Проверьте версию Java: нельзя считать, что встроенный в Android Studio JBR
обязательно версии 21 — новые установки Studio могут поставляться с JBR 25.
Используйте JBR 21, если он доступен, либо другой установленный JDK 21:
нативные тесты и Android Lint также проверены с Homebrew `openjdk@21`
21.0.12.1. JDK 25/26 не является поддерживаемым окружением сборки.
Укажите каталог JDK 21 в `JAVA_HOME`, Flutter
(`flutter config --jdk-dir="$JAVA_HOME"`) и Gradle
(`org.gradle.java.home` в `~/.gradle/gradle.properties`).

```bash
git clone https://github.com/RPG-18/snatch-dash.git
cd snatch-dash
flutter pub get
(cd packages/opendash_dash_engine && flutter pub get)
```

Плагину нужен собственный `pub get`: после свежего клона корневой resolve
не устанавливает dev-зависимости path-пакета, включая Pigeon.

### API-ключ Yandex (нужен для карты и поиска места назначения)

1. Сгенерируйте ключ на <https://developer.tech.yandex.ru/services/>. Yandex
   выдаёт один API-ключ, общий для всех картографических продуктов —
   он покрывает и MapKit Mobile SDK, и Geosuggest API, которые использует
   это приложение.
2. Добавьте его в `android/dart_defines.local.properties` (в `.gitignore`):

   ```properties
   YANDEX_API_KEY=your-key-here
   ```

   См. `android/dart_defines.defaults.properties` — там заготовка/шаблон.
   Это отдельный файл от `android/local.properties`, потому что парсер
   Flutter для `--dart-define-from-file` отклоняет ключи с точкой, такие
   как `sdk.dir`.

Без настоящего ключа приложение собирается и запускается, но карта остаётся
пустой, а поиск места назначения на экране «Маршрут» не возвращает
подсказок.

```bash
flutter build apk --debug --dart-define-from-file=android/dart_defines.local.properties
flutter run --dart-define-from-file=android/dart_defines.local.properties  # установка + запуск на подключённом устройстве/эмуляторе
```

### Анализ и тесты

```bash
flutter analyze
flutter test                                        # приложение: unit + widget-тесты
(cd packages/opendash_dash_engine && flutter test)  # Dart-тесты плагина
(cd android && ./gradlew :opendash_dash_engine:testDebugUnitTest)
(cd android && ./gradlew :opendash_dash_engine:lintDebug)
```

Android Lint проверяет совместимость с API-уровнями, которую не проверяют
Dart-анализатор и компилятор Kotlin. Запускайте его при изменениях нативного
Kotlin, манифестов или Gradle. При изменении API плагина перегенерируйте
границу из каталога плагина:

```bash
(cd packages/opendash_dash_engine && dart run pigeon --input pigeons/dash_engine.dart)
```

Тесты репозитория на `sqflite`
(`test/data/sqlite_garage_repository_test.dart`) используют
`sqflite_common_ffi` с изолированными временными файлами БД — устройство
или эмулятор не нужны.

## 🧭 Основные вкладки

| Вкладка | Что делает |
| --- | --- |
| Главная | Статус подключения, сохранённые места, недавние поездки |
| Техника | Добавление/редактирование техники и выбор активной |
| Расходы | Добавление, фильтрация, просмотр и экспорт расходов |
| Гараж | Пробег, расход топлива, расходники, журнал обслуживания |
| Ещё | Сопряжение с дэшем, работа в фоне, офлайн-карты, тема карты, валюта, голосовые подсказки, доступ к уведомлениям, логи, обновления |

## 🔐 Приватность

- Данные приложения хранятся только локально; нет аналитики, облачной
  синхронизации, аккаунта.
- Учётные данные Wi-Fi дэша хранятся через `EncryptedSharedPreferences`
  (нативная часть, `DashConfig.kt`).
- Экспорты расходов создаются локально и передаются наружу только тогда,
  когда вы сами решаете ими поделиться.

## ⚠️ Заметки

- Реальное поведение дэша зависит от прошивки (проверено только на
  **11.63**) и требует тестирования на железе — см.
  [`docs/ON_HARDWARE_VERIFICATION_RU.md`](docs/ON_HARDWARE_VERIFICATION_RU.md)
  перед тем, как полагаться на приложение в поездке.
- Автомобильным маршрутам Yandex MapKit и поиску места назначения нужен
  доступ в интернет. Карте на дэше — нет: она рисуется из скачанных паков,
  которые райдер выбирает сам в «Ещё → Оффлайн-карты».
- Поведение карточек медиа/звонков может отличаться в зависимости от версии
  Android, дайлера и медиа-приложения.
- Для поездок с выключенным экраном проверьте «Ещё → Работа в фоне» и
  дополнительные ограничения батареи производителя телефона. Для речи нужен
  установленный Android TTS-движок с голосовыми данными для языка устройства;
  при их отсутствии приложение не подменяет язык или речь звуковым сигналом.
