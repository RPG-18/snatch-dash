# Устройства

По файлу на телефон, который участвует в заездах. Здесь лежит то, чего нет
ни в коде, ни в git: **как конкретное железо ведёт себя с дэшем** — имя
аппаратного кодека и его повадки, поведение Wi-Fi-локов на этом API-уровне,
базовые линии телеметрии, от которых считается «нормально это или нет»,
и дефекты, которые на этом устройстве воспроизводятся, а на соседнем нет.

Заведено 2026-09-16, после того как разница между двумя телефонами оказалась
единственным, что указало на настоящую причину замирания карты
([`spec/video.md`](../../spec/video.md), «RTP-метка — счётчик кадров»).
Держать эти числа в голове больше нельзя.

## Что писать в файл устройства

Только то, что **измерено на этом устройстве** или прочитано с него. Источник
у каждого числа — ride-файл с датой или команда `adb`. Маркетинговые названия,
характеристики с сайта производителя и «обычно у таких телефонов» сюда не идут:
файл ценен ровно тем, что его нельзя было выдумать.

Разделы, которые себя оправдали: идентификация, что важно для дэша (кодек,
Wi-Fi, память), базовые линии телеметрии, известные особенности, история
заездов, и — отдельно — **чего не хватает**, с готовой командой, чтобы это
дополнить при следующем подключении.

## Как снять данные

Телефон подключён по USB, отладка включена:

```sh
adb shell 'getprop ro.product.manufacturer; getprop ro.product.model; \
  getprop ro.product.device; getprop ro.build.version.release; \
  getprop ro.build.version.sdk; getprop ro.build.display.id; \
  getprop ro.board.platform; getprop ro.sf.lcd_density'
adb shell head -3 /proc/meminfo          # MemTotal — сколько всего RAM
adb shell wm size; adb shell wm density
adb pull /sdcard/Android/data/ru.snatchdash.app/files/diag
```

Приоритеты потоков — на ЗАПУЩЕННОМ приложении (`plans/done/2026-09-16-frame-pipeline.md` §4.3 объясняет,
зачем):

```sh
pid=$(adb shell pidof ru.snatchdash.app)
adb shell cat /proc/$pid/limits | grep -i nice        # можно ли просить вообще
adb shell 'for t in /proc/'$pid'/task/*; do \
  n=$(sed "s/.*) //" $t/stat | awk "{print \$17}"); echo "$n $(cat $t/comm)"; \
done' | sort -n                                        # nice каждого потока
```

`Max nice priority 40` означает, что ядро пускает процесс до nice −20, то есть
`THREAD_PRIORITY_DISPLAY` (−4) будет выдан. **Число главного потока при этом
описывает состояние процесса, а не телефон**: на переднем плане с включённым
экраном оно одно, под foreground-сервисом с погашенным — другое. В файл
устройства идёт лимит и раскладка рабочих потоков, а не приоритет Main.

Имя кодека и его объявленный диапазон битрейта берутся не из `adb`, а из
ride-файла — строка `[stream] encoder …` пишется на каждом старте стрима.
