# Формат спеки

Спека в [`spec/`](../../../spec/) описывает, **как система устроена сейчас**, и
правится в том же коммите, что код. Её ценность не в полноте, а в том, что
её нельзя восстановить чтением кода: причины, даты полевых подтверждений,
отвергнутые гипотезы, границы владения между подсистемами.

Образцы: [`spec/home_screen.md`](../../../spec/home_screen.md) для экрана,
[`spec/frame_pipeline.md`](../../../spec/frame_pipeline.md) для подсистемы,
[`spec/k1g_protocol.md`](../../../spec/k1g_protocol.md) для контракта с
нумерованными инвариантами.

## Спека экрана

Шапка без заголовка раздела, три поля:

```
# Home Screen (Главная)

**Файл:** [`lib/screens/home_screen.dart`](../lib/screens/home_screen.dart)
**Виджет:** `HomeScreen` (`ConsumerStatefulWidget`)
**Route:** `/home` — чем открывается и откуда; если входов несколько,
перечислить все с указанием вызывающего файла.
```

Дальше: **Назначение** (2–4 строки), **Читаемое/изменяемое состояние**
таблицей «Провайдер | Для чего», **Разметка / действия** нумерованным списком
сверху вниз по экрану с указанием, какой метод какого провайдера вызывает
каждое действие, и **Заметки** — неочевидное поведение.

Если экран ещё не написан, это пишется прямо в шапке:
`**Файл:** lib/screens/offline_maps_screen.dart (не создан)`.

## Спека подсистемы

Шапка — список файлов. Дальше по надобности: «Из чего собран» таблицей
«Объект | Файл | Чем владеет», «Потоки» таблицей «Что | Где исполняется |
Почему именно там», инварианты, телеметрия с расшифровкой полей, «что
пробовали и отвергли по замеру».

Раздел «что отвергли» обязателен, если отвергали: без него следующий
исполнитель предложит то же самое. Формулировка включает дату и то, чем
опровергнуто.

## Правила, которые делают спеку полезной

- **Писать «почему», а не «что».** «RTP-метка — счётчик кадров, продвигаемый в
  `onEncoded`, а не время и не итерация цикла» плюс чем это кончилось, когда
  было иначе.
- **Дата у каждого факта из поля.** «Сверено 15.09: при выключенном экране
  `rx gap` совпал с Android 12».
- **Ссылки на строки кода** там, где утверждение надо перепроверить. Они
  съезжают; это допустимая цена, но в спеке подсистемы лучше ссылаться на
  файл и имя, а не на номер строки.
- **Разделение владения.** Соседние спеки владеют своими половинами и здесь
  не пересказываются: вместо пересказа — ссылка и одна фраза о том, что там.
  Пример формулировки в шапке `frame_pipeline.md`.
- **Нумерация инвариантов — часть контракта.** На инварианты K1G ссылаются по
  номеру пятнадцать тестовых файлов. Не перенумеровывать, новый пункт
  дописывать в конец.
- **Отладочное поведение и его отмена.** Когда отладочный путь убирают, в
  спеке остаётся абзац «этого больше нет, с такой-то даты, потому что», иначе
  его заведут снова.

## Чего в спеке нет

Дневника работ, замеров, обоснования выбора между вариантами, снимков «как
было» — это принадлежит плану (`plan-format`). Пересказа кода строка в
строку: если утверждение читается из кода за минуту, его место в коде, а не в
спеке.

## При создании новой спеки

1. Файл `spec/имя.md` латиницей, snake_case.
2. Добавить строку в индекс в [`CLAUDE.md`](../../../CLAUDE.md): в список
   экранов, если это экран, или в «Ещё спецификации» с одной фразой о
   содержимом. Спека, которой нет в индексе, для следующей сессии не
   существует.
3. Проставить перекрёстные ссылки в соседних спеках, которых она касается.
