# snatch-dash

**snatch-dash** — открытое приложение-компаньон для совместимого байк-дэша:
навигация, история поездок, учёт обслуживания мотоцикла, расходы и
карточки медиа/звонков в одном лёгком Flutter-приложении. Приложение рендерит
собственное изображение для дэша за кадром, кодирует его в H.264 и стримит по
WiFi на физический дэш, так что экран телефона может оставаться выключенным
во время поездки.

Изначально это был **Flutter-порт [subtlesayak/open-dash](https://github.com/subtlesayak/open-dash)**
(оригинальное нативное приложение на Kotlin/Compose), переведённый на
**Yandex MapKit** вместо Google Maps, чтобы надёжно работать на территории
Российской Федерации. Только Android (каталога `ios/` нет); нативный движок,
работающий с дэшем, находится в локальном пакете-плагине
[`packages/opendash_dash_engine`](packages/opendash_dash_engine).


Yandex MapKit не предоставляет API для захвата изображения карты и маршрута, для последующей отправки на
дэш мотоцикла. Изначально использовался сервис Maptiler как источник растровых тайлов, но пришлось отказаться от него из-за:
- низкие лимиты на тарифах Free, Flex
- очень дорого иметь свою инфраструктуру, такую как OpenFreeMap.
Поэтому теперь приложение рисует карту, используя скачанные тайлы с S3. Карты сохраняет в каталог
`getExternalFilesDir(null)/maps/` — качает их системный `DownloadManager`, а он во внутренние
каталоги приложения писать не умеет. Каталог обязан быть исключён из Auto Backup
(`dataExtractionRules` + `fullBackupContent`), иначе первый же пак ломает бэкап базы —
подробности в [спеке отрисовки](./spec/drawing_from_local_tiles.md), «Хранение паков».


Локализовано на RU/EN (по языку устройства, без переключателя в интерфейсе)
через сгенерированный `AppLocalizations` — см. [`lib/l10n/`](lib/l10n).

## Навигация

Нижняя панель из 5 вкладок (`AppShell`,
[`lib/router/app_shell.dart`](lib/router/app_shell.dart)), маршруты заданы в
[`lib/router/app_router.dart`](lib/router/app_router.dart): **Главная**,
**Техника**, **Расходы**, **Гараж**, **Ещё**. Экраны Route/Dash/Rides
открываются поверх ветки Home.

Маршрут автоматически [перестраивается при отклонении](./spec/route_restructuring.md)

## Экраны

Для каждого экрана в [`spec/`](spec) есть отдельное описание: назначение,
Riverpod-провайдеры, которые экран читает/пишет, макет/действия и неочевидные
детали поведения:

- [Главная](spec/home_screen.md) — `/home`, стартовая вкладка: статус подключения, быстрые действия, сохранённые места, сводка по поездкам
- [Маршрут](spec/route_screen.md) — `/home/route`, поиск/предпросмотр места назначения
- [Превью Маршрутов](spec/route_preview_screen.md) - `/home/route-preview`, выбор из найденных маршрутов на карте + «Отправить на Dash»
- [Dash](spec/dash_screen.md) — `/home/dash`, карта Yandex с маршрутом и положением райдера + подключение/отключение
- [Техника](spec/vehicles_screen.md) — `/vehicles`, профили техники (добавление/редактирование/выбор активной)
- [Расходы](spec/expenses_screen.md) — `/expenses`, список расходов с фильтрами/добавлением/экспортом
- [Гараж](spec/garage_screen.md) — `/garage`, пробег, заправки, интервалы обслуживания
- [Поездки](spec/rides_screen.md) — `/home/rides`, история поездок
- [Настройки («Ещё»)](spec/settings_screen.md) — `/more`, сопряжение с дэшем, офлайн-карты, тема карты, валюта
- [Оффлайн-карты](spec/offline_maps_screen.md) - `/more/offline-maps`, работа с офлайн картами

Отдельно — [конечный автомат](spec/fsm.md) того, что физически видно на
приборке дэша (карта без маршрута / карта навигации / собственный экран прошивки)
в зависимости от того, что происходит на этих экранах.

Ещё спецификации:
- [wifi retry policy](spec/wifi_retry_policy.md) стратегия переподключения к WiFi мотоцикла.
- [сервер карт](spec/remote_map_server.md) формат офлайн-тайлов, `index.json` и протокол скачивания паков.
- [отрисовка из скачанных тайлов](spec/drawing_from_local_tiles.md) как кадр дэша получается из локального пака (MapLibre offscreen, стиль, несколько источников).

## Сборка и тесты

Сборке нужен **JDK 21 — JBR из Android Studio**, а не `openjdk` из Homebrew: там
26, и на нём AGP падает — `jlink` не может трансформировать
`core-for-system-modules.jar`. На машине разработчика прописано разово в трёх
местах, потому что двух не хватает: `JAVA_HOME` в `~/.zprofile`,
`org.gradle.java.home` в `~/.gradle/gradle.properties`, `flutter config
--jdk-dir`. Переменная нужна именно в окружении — лаунчеру `gradlew` нужен
`java`, чтобы стартовать и дочитать до `gradle.properties`.

```
flutter analyze
flutter test                                              # плюс 3 теста в packages/opendash_dash_engine
cd android && ./gradlew :opendash_dash_engine:testDebugUnitTest
flutter build apk --debug --dart-define-from-file=android/dart_defines.local.properties
```

**Ключ Яндекса идёт только флагом `--dart-define-from-file`** (шаблон —
`android/dart_defines.defaults.properties`, реальный ключ в gitignore'нутом
`.local.properties`). Без него сборка проходит, но карта пустая, а поиск на
экране «Маршрут» молчит.

## Полевые логи с дэша

Приборка работает при выключенном экране телефона, поэтому единственный
пост-мортем — файлы на устройстве. Ничего, кроме кабеля, не нужно:

```
adb pull /sdcard/Android/data/ru.snatchdash.app/files/diag   # по файлу на сессию: [map], [session], [stream]
adb exec-out run-as ru.snatchdash.app cat files/app_log.txt > app_log.txt
```

`diag/` лежит на внешнем хранилище и тянется без root; `app_log.txt` —
внутренний, достаётся через `run-as` (работает на debug-сборке). Нативный лог
MapLibre отдельно ловить не нужно: `MapLibreLogBridge` заворачивает его в тот же
`DebugLog`, поэтому имя недостающего ассета попадёт в оба файла само. Кольцевой
буфер `adb logcat` живёт минуты и к возвращению телефона на стол пуст — на него
не рассчитывать.

**Мерить производительность на debug-сборке нельзя**: Flutter в JIT с asserts,
`debuggable=true` гасит оптимизации ART и включает CheckJNI на JNI-плотном пути
MapLibre. Для замеров — `--profile`.

## Заметки
- разрешение на GPS запрашивается при старте приложения
- каталог `re_app/` содержит оригинальное декомпилированное приложение. В репозиторий он не входит и на диске может отсутствовать. Не смотри в него, когда дело касается Dart/Flutter; использовать только по моей команде.
